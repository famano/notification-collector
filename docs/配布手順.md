# 配布と初回設定

開発機ではなく、**利用者の PC で動かすための手順**。
「シェルにコマンドを打つ」「環境変数を設定する」「開発者向けのトークンを自分で取る」を
利用者側に残さないことを目標にしてある。

| | 配る人 (エンジニア) | 使う人 |
|---|---|---|
| 用意するもの | Claude の API キー (と任意で組織 ID)、(任意で) Google の OAuth クライアント、Slack アプリ、Microsoft 365 のアプリ登録 | 自分の Google / Slack / Microsoft / GitHub アカウント |
| 触るもの | `config\app-config.json`、ZIP | `Install.cmd` とデスクトップのアイコン、カンバンの「接続」 |
| 使うもの | 端末 | ブラウザだけ |

---

## 配る人の手順

### 1. 資格情報を用意する

利用者の権限では取れないものだけを、こちら側で用意する。

| 何 | どこで | 無いとどうなるか |
|---|---|---|
| Claude の API キー | https://console.anthropic.com/settings/keys | **カードが1枚も作られない**（取り込みだけが動く） |
| Google の OAuth クライアント (デスクトップ アプリ) | Google Cloud。Gmail API と Calendar API を有効化 | 利用者が自力で Google Cloud にプロジェクトを作る羽目になる |
| Slack アプリ（User Token Scopes のみ）+ 中継ページ | https://api.slack.com/apps | 利用者は Slack に繋げない（アプリを作る権限が要る） |
| Microsoft 365 のアプリ登録（クライアント ID、必要ならシークレット） | https://entra.microsoft.com/ → アプリの登録 | 利用者は Outlook / Teams に繋げない（テナントにアプリを登録する権限が要ることが多い） |
| Claude の組織 ID（任意） | Console の Settings → Organization | 困らない。動かすのには要らない。入れておくと「別の組織のキーを貼った」を接続時に知らせ、URL に組織 ID が要る API をワーカーが自分で組み立てられる |

GitHub のトークンは**個人のもの**なので、ここでは用意しない。利用者が画面から入れる。

**Microsoft のクライアント シークレットは普通は要らない。** アプリ登録で
「パブリック クライアント フローを許可する」を「はい」にできれば、クライアント ID だけで繋がる。
テナントの方針でそれができない (機密クライアントしか置けない) 場合だけ、
「証明書とシークレット」でシークレットを発行して同梱する。シークレットには**有効期限**があるので、
切れる前に差し替えて配り直すこと (切れると `AADSTS7000222` で全員が繋がらなくなる)。

### 2. `config\app-config.json` を作る

```powershell
copy config\app-config.sample.json config\app-config.json
```

用意できたものだけを書く。空欄の項目は無視される。

```json
{
  "anthropic": { "apiKey": "sk-ant-...", "organizationId": "00000000-..." },
  "google":    { "clientId": "....apps.googleusercontent.com", "clientSecret": "..." },
  "slack":     { "clientId": "...", "clientSecret": "...",
                 "redirectUrl": "https://<あなた>.github.io/notification-collector/slack-oauth-redirect.html" },
  "microsoft": { "clientId": "00000000-...", "tenantId": "", "clientSecret": "" },
  "startup":   { "port": 8787, "openBrowser": true }
}
```

- 起動時に **DPAPI の保管庫へ取り込まれる**。取り込んだあとはこのファイルから値を消してよい。
- **すでに保管庫にある項目は上書きしない。** 利用者が画面から入れ直した値が、
  次の起動で配布時の値に戻ることはない。
- このファイルは平文なので `.gitignore` してある。ZIP に同梱する場合は渡し方に注意する。
- Google は「クライアントの ID と秘密」だけを配る。**どのメールボックスを見るかは
  利用者が自分で同意する。**こちらのアカウントには一切触れない。
  Microsoft も同じで、配るのはアプリ登録だけ。サインインは利用者が画面に出るコードで行う。
- `anthropic.organizationId` と `microsoft.tenantId` は秘密ではない。残しておいても
  「平文で残っています」とは言われない。
- Claude の**管理 API キー**（`sk-ant-admin...`、組織の利用状況などを叩くときだけ要る）は
  ここには書けない。組織の管理権限そのものなので、要る人だけがカンバンの「接続」から入れる。

### 3. フォルダごと渡す

ZIP に固めて渡す。`phase1/data`・`phase2/data`・`phase5/data`・`logs`・`phase4/output` は
入れない（他人の業務データと資格情報が入っている）。

```powershell
# 例: 実データを除いて固める
$ex = @('phase1\data','phase2\data','phase5\data','phase4\output','logs','.git')
```

### 4. 伝えること

> 展開して `Install.cmd` をダブルクリック。あとはデスクトップの「通知コレクター」から。

これ以上は要らない。足りない設定は画面が言う。

### 5. Slack だけは中継ページが1枚要る

Slack の OAuth は**戻り先に HTTPS を要求する**。Google のように
`http://127.0.0.1:8787/...` を登録できないので、そのままではデスクトップのアプリに
戻ってこられない。そこで、**転送しかしない静的ページ**を1枚だけ公開する。

```
利用者のブラウザ ── 同意 ──▶ Slack ──▶ 中継ページ (HTTPS・公開) ──▶ http://127.0.0.1:8787/oauth/slack/callback
                                          ↑ 転送だけ。秘密も状態も持たない        ↑ ここで初めてトークンに引き換える
```

手順:

1. このリポジトリの `docs/slack-oauth-redirect.html` を公開する
   （GitHub Pages を `docs/` から公開するのが最短。専用のサーバは要らない）
2. Slack アプリの **OAuth & Permissions → Redirect URLs** に、その URL をそのまま登録する
3. 同じ URL を `config/app-config.json` の `slack.redirectUrl` に書く
4. **User Token Scopes** に以下を足す（Bot Token Scopes は空のままでよい）

   ```
   channels:history groups:history im:history mpim:history
   channels:read    groups:read    im:read    mpim:read
   users:read  files:read  chat:write
   ```

中継ページを通るのは**単回・短命の認可コードだけ**で、トークンへの引き換えには
client secret が要る。それは利用者の PC にしか無いので、**この公開ページは
トークンを一度も見ない。**ページ自身も外部リソースを読まず、何も保存しない。

**Bot トークンは使わない。読み取りも返信も本人のトークン1本である。** Bot は招待された
チャンネルしか読めず、DM に至っては Bot 自身宛しか見えないので、「本人に届いたもの」を
拾うこのアプリとは噛み合わない。返信の側も同じで、**会話の続きは本人名義で出なければ
相手に通じない。** ユーザートークンにすると、チャンネルへの招待作業も消える。

**ワークスペースによっては、アプリの利用に管理者の承認が要る。** 配る前に確認すること。

### 6. 何から守れて、何から守れないか

同梱は便利だが、**平文の JSON を配ること**でもある。何が守られていて何がそうでないかを
はっきりさせておく。

| 想定するもの | 守れるか | 理由 |
|---|---|---|
| フォルダごと別の PC・別アカウントにコピーされる | ○ | 資格情報は DPAPI (CurrentUser) で暗号化され、持ち主以外は復号できない。`app-config.json` と `secrets.dat` はファイル権限も本人だけに絞る |
| 同じ PC の別の Windows アカウント | ○ | 同上。ただし**管理者は所有権を取れる** |
| **同じユーザーで動く別のアプリ (マルウェアを含む)** | **×** | DPAPI の保護境界は「ユーザーとマシン」であって「アプリケーション」ではない。そのユーザーとして動くプロセスは、保管庫も配布設定も等しく読める。資格情報マネージャに移しても同じ |
| 悪意ある Web ページがカンバンを叩く | ○ | 127.0.0.1 バインド + Host ヘッダ検証 (DNS リバインディング対策) + 非 GET の Origin 検証 (CSRF 対策)。GET の応答は同一オリジンポリシーで読めない |
| 同じ PC の別のローカルサーバが出したページ | ○ | Origin は**このカンバン自身のポート**とだけ照合する (localhost なら何番でも通す作りだと、開発サーバや他のアプリのローカル UI から操作を起こせる) |
| **同じ PC のネイティブなプロセスがカンバンの API を叩く** | **×** | API に認証が無い。Origin を見る検査は**ブラウザが付けるヘッダ**に頼っているので、`curl` 相当のものには効かない。ただし **API から資格情報そのものは取り出せない** (返るのは「設定済みか」と接続先のアカウント名だけ)。できてしまうのはカードの閲覧、承認、カードからの送信 |
| 悪意あるブラウザ拡張 | × | 拡張はページと同じオリジンで動ける |
| 配った相手がキーを別の用途に使う | × | **同梱した時点で、そのキーは相手のもの**。技術では防げない |

つまり同梱してよいのは「**その人たちと共有してよいキー**」に限られる。
共有したくないなら欄を空のまま配り、各自に画面から入れてもらう
(その場合も画面から入った値は同じ DPAPI の保管庫に入る)。

### 7. キーを同梱するなら、運用で締める

- **利用者ごとに別のキーを発行する。** 失効させるときに1人分で済む
- Anthropic Console でワークスペースを分け、**支出上限 (spend limit) を設定する**
- 取り込みが済んだら `app-config.json` の資格情報の欄を空にする
  (起動時に「平文で残っています」と出る)
- ZIP をメールで回さない。経路とバックアップに残る
- 退職・PC 入れ替えのときにキーを失効させる

## 使う人の手順

1. 受け取ったフォルダを展開する（デスクトップやドキュメントなど、書き込める場所へ）
2. `Install.cmd` をダブルクリックする
   - デスクトップに「通知コレクター」ができる
   - サインイン時の自動起動を聞かれる（後から `Install.cmd` で変えられる）
3. 「通知コレクター」をダブルクリックする
   - ブラウザでカンバンが開く
   - 窓（黒い画面）は**閉じない**。閉じると止まる。最小化しておけばよい
4. まだ接続していないものがあれば、カンバンの右上「接続」から入れる
   - **Claude** … これが無いとカードは作られない。配布時に設定済みなら何もしなくてよい
   - **Gmail / カレンダー** … ボタンを押して Google の画面で許可する
   - **Slack** … 「Slack に接続する」を押して許可する（自分のアカウントとして繋がる）
   - **Microsoft 365** … 「Microsoft 365 … に接続する」を押し、出てきたコードでサインインする
   - **GitHub / Chatwork / Backlog** … 使う場合だけ

   Claude 以外は、**使っていないなら繋がなくてよい。** 「接続」ボタンの数字に出るのは
   次のどれかに当たる未接続だけ:
   - 「使う（未接続なら知らせる）」を押したもの（一度繋いだものも含む）
   - 実際にそのアプリから通知が届いているもの（直近 30 日）
   - ワーカーがその権限不足で止まり、設定カードが立っているもの

   あえて繋がないなら、そのサービスの「このサービスは警告しない」を押せば数字から消える。
5. 止めるときは `Stop.cmd`、または窓を閉じる

API キーを入れた直後に判定とワーカーが動き始める。**起動し直す必要はない。**

## よくある詰まり

| 症状 | 原因 | 直し方 |
|---|---|---|
| アイコンを押しても何も起きない | ZIP のファイルがブロックされている | `Install.cmd` を実行し直す（ブロックを外す） |
| 「WindowsによってPCが保護されました」 | SmartScreen | 「詳細情報」→「実行」。配布元が自分だと分かっている場合のみ |
| カードが増えない。取り込みは動いている | Claude の API キーが未設定 | カンバン上部の警告から「ここで設定する」 |
| 起動直後に「接続の確認に失敗しました」 | 別の PC / 別のユーザーで作られた `phase5\data\secrets.dat` を持ってきた | そのファイルを削除して、画面から入れ直す（DPAPI は持ち主以外復号できない） |
| ポートが使われていて開かない | 8787 が別のアプリと衝突 | `config\app-config.json` の `startup.port` を変える |
| 画面が真っ白 | ブラウザのキャッシュ | 再読み込み。直らなければ `Stop.cmd` → もう一度起動 |

## 更新の配り方

フォルダを丸ごと置き換える。`phase1/data`・`phase2/data`・`phase5/data`（カードと資格情報）は
**残す**こと。消すと設定と履歴が消える。

## 消すとき

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1 -Uninstall
```

ショートカットだけが消える。データを消すにはフォルダごと削除する。
