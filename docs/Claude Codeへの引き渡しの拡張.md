# Claude Code への引き渡しを広げる (設計メモ・未着手)

いまの引き渡し (#30) は **GitHub のリポジトリのコード修正**だけを対象にしている。
Claude Code はコード以外にも多くの作業ができるので、「複雑なファイル操作が要る作業」全般に
広げたい。ここではその設計を決めておく。実装はまだしていない。

## いまの設計の安全性は git が支えている

| 性質 | git での実現 | 無いと起きること |
|---|---|---|
| 隔離 | 新しいブランチの worktree で作業する | 利用者のファイルを直接いじる |
| 見える差分 | 下書きの PR で確かめてからマージする | 何が変わったか分からないまま反映される |
| 戻せる | マージしなければ何も起きない | 壊したら終わり (#295 と同じ) |

git を外すなら、この3つを別の手段で持たせる。持たせられれば、git は必須でなくなる。

## 作業場所を3種類にする

引き渡しの `repo` (owner/name) を、「どこで作業するか」を表す `target` に一般化する。

### 1. 作業場所を持たない作業 (生成物を作る)

- 例: 添付の Excel を変換・集計する、複数のファイルから資料を組み立てる
- カードの作業フォルダ (`phase4/output/task-NNNN`) の中で Claude Code を動かし、
  できたものはそのままカードの成果物に載せる
- 添付は `fetch_attachment` ですでにこのフォルダに落ちているので、自然につながる
- 手元のファイルに触らない。**一番安全で、一番小さく作れる。最初にやる**

### 2. 手元のフォルダ (git ではない)

- 例: 共有フォルダの整理、ドキュメントの一括修正
- **元のフォルダでは作業させない。コピーの上で作業させる**。終わったらカードに差分
  (追加・削除・変更されたファイルと中身) を出し、利用者が「反映」を押したときだけ元に書き戻す。
  書き戻す前に元の状態をバックアップする。PR とマージを自前で持つ形
- フォルダの指定は、ワーカー (モデル) が第三者の文面から組み立てたものになる。
  git 版の origin 照合の代わりに、**初回は利用者が画面で許可したフォルダだけ**を通す
  (許可したフォルダは覚える。許可の一覧はヘッダの「方針」から消せるようにする)
- 大きすぎるフォルダはコピーの負担が大きいので、上限 (ファイル数・合計サイズ) を設けて断る
- 反映は「差分を見た時点の元の状態」と今の元の状態が変わっていないかを確かめてから行う
  (その間に利用者が元を触っていたら、上書きせずに止める)

### 3. git のリポジトリ

- いまのまま (新しいブランチの worktree → 下書きの PR)

## 広げても変えない線

**Claude Code に渡すのは、手元で完結する作業だけ。**

- Windows では Claude Code のサンドボックスが効かず、Bash からの通信を止められない
- 外部サービスへの書き込みや送信まで任せると、ワーカー側で作った関門
  (種類 × ホストの許可、書く前の突き合わせ、承認) を丸ごと迂回される
- 外に出る操作 (送信・push・反映) は、これまでどおり**こちらのコードが利用者の1押しのあとで行う**

## ワーカーへの伝え方

`beyond_tools` の判断基準を「コード修正なら引き渡す」から
「**手元のファイルを正しく・確かめながら扱う必要がある作業なら引き渡す**」に広げる。
`require_human_step` の入力は次の形にする。

| target | 入力 | 作業場所 |
|---|---|---|
| `workspace` | なし | カードの作業フォルダ |
| `folder` | フォルダのパス | そのコピー (反映は利用者の1押し) |
| `repo` | owner/name | 新しいブランチの worktree (いまの形) |

## 進め方

1 → 2 の順。1 で「複雑なファイル操作」の多くは片付くはずなので、1 を使ってみてから 2 を判断してもよい。
