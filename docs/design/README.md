## 読み方

どの文書も同じ並びにしてある。

1. **役割と境界** — 担うもの / 担わないもの。意図的に境界を越えている例外とその理由
2. **構成要素・データモデル** — 何があるか
3. **不変条件** — 守っていること × 担保している場所 × **破れたときの症状**
4. **主要な流れ** — 実際の呼び出し順
5. 以降は対象ごと (同時実行、移行の作法、費用、設定できるもの…)
6. **テスト** — どのテストが何を見ているか
7. **いま抱えている歪み** — 直すつもりのないものも含めて正直に

**3 (不変条件) が一番効く。** ここで守っているものは、破れても例外が飛ばず
**症状だけが出る** ―― 「カードが増える」「本物のメールが1通消える」「請求額が上がる」。
症状から担保している場所を引けるように、対で書いてある。

## 手を入れるとき

- 新しい不変条件を足したら、**その文書の 3 とテストの両方に足す。**
- 行番号は書かない (コードが動くとずれる)。参照は関数名・列名・ファイル名で。
- 過去に踏んだ事故は、症状と対策を対で残す。**理由の消えた対策は、次の人に消される。**
