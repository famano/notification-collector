# Phase 3 — カンバンボード UI

タスクストアを**ユーザーが操作できる**ようにする層。割り込み・修正・新規起票をここで行う。

| ファイル | 役割 |
|---|---|
| `Start-Board.ps1` | `HttpListener` によるローカル Web サーバと JSON API |
| `wwwroot/index.html` | UI 一式（依存ライブラリなし・単一ファイル） |

## 使い方

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\phase3\Start-Board.ps1
```

ブラウザが `http://localhost:8787/` で開く。`-Port` で変更、`-NoBrowser` で自動起動を抑止、
`-DbPath` で別の DB を見る。管理者権限は不要（localhost へのバインドは URL 予約なしで通る）。

## できること

| 操作 | 挙動 |
|---|---|
| カードをドラッグ | 列を移動。`version` を添えて送るので競合したら 409 で拒否される |
| **実行中から外へドラッグ** | `cancel_requested` が立つ。**これが割り込みの信号** |
| カードをクリック | 詳細ドロワー。判定理由・提案アクション・**ワーカーの作業ログ**・元の通知 |
| 「元を開く ↗」 | 元のメッセージを別タブで開く。カードの右下と、ドロワーの見出し横に出る |
| **「送る文面」** | 返信先があるカードで出る。**「この内容で送る」でそのまま送信され、完了に移る** |
| **「対応の記録」** | 返信先が無いカードで出る。**「これで完了にする」で保存して完了に移る**。空でもよい |
| 「保存」 | まだ閉じないとき。`user_edited` に入り、`agent_output` は上書きしない |
| 「報告を取り込む」 | ワーカーの報告を編集欄にコピーして手直しする |
| 「作業を中止」 | `cancel_requested` を立てる |
| コメント | `task_comments` に積む。ワーカーは次の実行前にこれを読んで方針を立て直す |
| 「アーカイブ」 | ボードから隠す。ヘッダの「アーカイブ」から一覧・復元できる |
| 「削除」 | 確認のうえ完全削除。作業ログとやりとりも消える |
| 「まとめて削除」 | 完了・対応不要・アーカイブ済みの見出しに出る。その列のカードを確認のうえ一括で完全削除 |
| 「+ カード」 | 通知に紐づかないカードを手で起票 |
| 「?」 | 列とラベルの意味を説明するパネル |

ヘッダにはワーカーの状態（作業中 / 承認待ち / 待機中 / 停止中 / エラー）と、
いまどのカードで何をしているかが出る。処理中のカードは枠が緑になる。

止まっている常駐があれば、ボード上部に赤い帯で出す。止め方が2種類あるので別々に見る。

| 止まっているもの | 起きること | 帯の内容 |
|---|---|---|
| 収集 (`Start-Collector.ps1`) | 新しいメールも通知もカードにならない | 「取り込みが止まっています」 |
| ワーカー (`phase4\Start-Worker.ps1`) | カードは増えるが誰も着手しない | 「要対応のカードには誰も着手しません」 |

収集が止まっているときの見え方は「要対応が 0 件」であり、
**何も来ていない状態と見分けが付かない。** だから静かなときほど明示する必要がある。
死活は収集が `settings` の `collector.*` に、ワーカーが `worker_state` に書く。
トリアージは 1 件ずつ LLM を呼んで数分かかることがあるので、
収集の「止まった」判定はワーカー (90 秒) より長い 15 分にしてある。

## ツール実行の承認

ワーカーが危険なツール（コマンド実行・外部通信・作業フォルダ外への書き込み）を
使おうとすると、ボード上部に承認パネルが出てワーカーは停止する。

**実行内容は省略せずに表示する。** コマンド本文や URL がそのまま出る。
通知やメールの本文がワーカーの入力に混ざる以上、ここが注入と実行のあいだに立つ
唯一の壁になるため、要約で済ませてはいけない。

選べるのは、許可 / 拒否 / このカードでは以後許可 / 今後すべて許可。
「まとめて許可」はヘッダ下に一覧として残り、`×` でいつでも取り消せる。
ヘッダの「自動承認」ボタンで YOLO にもできる（有効化時に何が起きるか確認を出す）。

## カードの出口

**カードは「何をもって完了とするか」で2種類しかない。**

- **送る** — 返信・投稿で終わるもの。宛先がカードの元イベントから束縛できる
- **実施** — 自分が手を動かして終わるもの。送り先が無い（PC の内部通知、手起票）

どちらも最後に残るのは1つのテキストで、違うのは押すボタンだけ。

| 出口 | 欄 | 主ボタン |
|---|---|---|
| 送る | 送る文面（宛先を上に赤帯で出す） | この内容で送る |
| 実施 | 対応の記録 | これで完了にする |

**この欄を作り直したのは、以前の「自分の下書き / 修正」が出口を持っていなかったため。**
保存しても起きるのは「次の実行時にプロンプトへ渡る」だけで、実際に外へ出るのは
ワーカーが書いた `.eml` や Gmail 下書きだった。つまり欄を直しても成果物は変わらず、
直したければ結局コメントで指示してワーカーに書き直させることになる。
使われなくて当然で、欄のほうが間違っていた。いまは**書いた内容がカードを閉じる操作に
直結する**（送る／完了にする）。

「実施」側の欄を「メモ」と呼ばないのは、そこに書かれるのが**「なぜ自分はこれを完了に
したのか」**だから。カンバンで完結するというのは、通知欄を見ないことに加えて、
後からその判断を辿れることでもある。

テキストは3つに分けて持つ。役割が違うものを1つの箱に入れない:

| カラム | 中身 | 上書き |
|---|---|---|
| `agent_output` | 何をしたか・何を確認すべきかの報告 | 実行のたびに |
| `draft_text` | ワーカーが提案する、外に出る文面 | 実行のたびに |
| `user_edited` | **利用者が確定させた版。これが実際に送られる** | **しない** |

欄は `user_edited ?? draft_text` を出す。ワーカーが何度作り直しても、
手を入れた内容は消えない ―― 元からの設計方針をそのまま維持している。

**送信は、モデルではなく人が押す操作。** 取り消せないので条件を厚くしてある:

- **宛先はサーバがカードの元イベントから決める。リクエストの宛先は受け取らない。**
  受け取れる作りにすると、ボードに載った第三者の文面から宛先を差し替える道ができる
- `confirm` が無いと送らない（UI の確認ダイアログを通った印）
- 送る文面は先に `user_edited` へ保存する。送ったものと残るものを一致させる
- `version` を照合する。画面が古いまま押したら 409 で止める
- 送信後は作業ログに `sent` として残り、カードは完了へ移る

## 設計上の判断

**状態を変える要求は `Origin` も見る。**
ボードから送信できるようにした以上、`Host` の検証だけでは足りない。
ブラウザは別サイトからの POST に必ず `Origin` を付けるので、外のページが
`localhost:8787` を叩いて削除や送信を起こす経路をここで塞ぐ（GET は対象外）。

**SSE ではなくポーリングにした。**
当初は SSE を想定していたが、PowerShell 5.1 の `HttpListener` は単一スレッドで回るため、
接続を張りっぱなしにするとリクエストループが止まる。ランスペースを使えば回避できるが、
一人で使うローカルボードには複雑すぎる。代わりに**安い `/api/rev`（件数と最終更新時刻）を
1.5 秒間隔で叩き、変化したときだけボード全体を取り直す**方式にした。

**入力中はドロワーを再描画しない。**
ポーリングで再描画すると、入力途中のコメントや下書きが消える（実装中に実際に踏んだ）。
`drawerBusy()` でドロワー内にフォーカスがあるかを見て、その間は作り直さない。
ボード側は更新されるので、他の変更は見える。

**表示は必ず `textContent`。**
カードには Slack のメッセージ本文がそのまま載る。`innerHTML` を使うと第三者のメッセージから
DOM を注入できてしまうため、UI は全要素を `createElement` + `textContent` で組んでいる。

**元のメッセージへのリンクだけは踏めるようにし、スキームを許可制にした。**
当初はリンクも文字列として出すだけにしていたが、それでは元の会話を確かめるのに
URL をコピーして貼り直すことになり、「カンバンだけで完結する」という前提が崩れる。
いまはカードの右下と、ドロワーの見出し横に「開く」を出す。

踏ませる以上、危ないのは本文ではなく `href` なので、そこだけ絞る:

- スキームは `https / http / mailto / slack / msteams` の許可制。`javascript:` `data:`
  `file:` は入り口で落とす。判定はサーバ (`Get-SafeOpenLink`) とクライアントの両方で行う。
- 制御文字や空白を含む URL は弾く。改行でスキーム判定をすり抜ける細工があるため。
- 表示するラベルは常に自前で決める（`Slack で開く` など）。通知が持ってきた文字列を
  リンクの見た目にはしない。飛び先そのものは「元の通知」の中に別途、文字列として出す。
- `target="_blank"` + `rel="noopener noreferrer"`。

Slack は Phase 5 の補完時に `chat.getPermalink` の結果を `events.permalink` に残してあり、
それがあれば `slack://` ではなく https の permalink を開く。

**127.0.0.1 のみにバインドし、`Host` ヘッダも検証する。**
ボードには業務上のメッセージが載るので外部に露出させない。

**生の enum を画面に出さない。**
`doing` `normal` `v20` のような内部値をそのまま出すと意味が伝わらない（実際に指摘を受けた）。
`列 実行中` `緊急度 中` `版 20` のようにラベルと日本語値で表示し、
各ラベルに説明を tooltip で付け、「?」パネルに一覧を置いた。

**操作の結果を必ず画面で返す。**
ボタンは押した瞬間に無効化して「保存中…」に変わり、完了時に緑（成功）か赤（失敗）の
トーストを出す。押しても何も起きないように見える状態を作らない。

**強弱をつける。**
全部を同じ濃さで出すと、どこを見ればいいのか分からなくなる（実際に指摘を受けた）。
いま強調しているのは、カードのタイトル、緊急度「高」、成果物の有無、
着手されない状態の警告だけ。ID・種別・版といった補助情報は小さく淡い一行にまとめ、
緊急度はタグではなくカード左端の色帯で示している。
列も、見るべき列（要対応・実行中・レビュー待ち）だけ色を持たせ、
完了と対応不要は沈めている。

**長くなるものは既定で畳む。**
作業ログとやりとりは際限なく伸びるため、開いた直後に見えるのは
「成果物」と「このカードの出口（送る文面 / 対応の記録）」だけにした。判定理由・報告・作業ログ・やりとり・元の通知は
折りたたみで、開閉状態はカードを開き直しても保たれる。

**指示欄は複数行。**
`input` だと改行が打てず Enter が即送信になっていた。`textarea` にして、
Enter は改行、送信は Ctrl+Enter か「指示を送る」ボタンにした。
表示側も `white-space: pre-wrap` で改行を保つ。

**やりとりは入力欄が先頭、履歴は新しい順。**
古い順に積むと、増えるほど入力欄が下に逃げてスクロールが必要になる。

**一括削除は、押した時点の列をサーバ側で確かめ直す。**
ボードは 1.5 秒ごとに更新される。画面が古いまま「まとめて削除」を押すと、
その間に別の列へ移ったカードまで消えかねない。UI は見えている id を送るが、
サーバはその id のうち**いまその列にあるものだけ**を消し、残りは `skipped` として返す。
削除自体は 1 トランザクションで行うので、途中で外部キーに引っかかっても
「何枚かだけ消えた」状態にはならない。出すのは片付いた列（完了・対応不要・
アーカイブ済み）だけで、未分類や要対応には出さない。まだ見ていないものを
一掃できてしまうため。

**成功を名乗る前に応答を見る。**
削除が外部キー制約で失敗しているのに「削除しました」と表示していた（実際に踏んだ）。
状態を変える操作は、ステータスと `ok` を確認してからトーストを出す。

**パネル外のクリックで閉じる。**
ただしカードの上は除く（別のカードへの切り替えとして扱う）。
未保存の編集があるときだけ確認を挟む。

## 検証済みの範囲

ブラウザで実際に操作して確認した:

- ボードの描画、詳細ドロワーの表示
- 下書きの保存 — `user_edited` に入り、`agent_output` は変化しない
- **カードの出口** — 返信先があるカードで「送る文面」と宛先が出ること、
  無いカードで「対応の記録」が出ること。「これで完了にする」で本文が保存され、
  作業ログに残り、カードが完了へ移ることをブラウザで実際に操作して確認
- **送信の門** — `confirm` 無し / 本文が空 / 送り先が無いカードは 400、
  古い `version` は 409、外部 `Origin` からの POST は 403 になること
- **元のメッセージへのリンク** — カードとドロワーに出ること、
  `href` が `rel="noopener noreferrer"` 付きで許可スキームのみになること
- **楽観ロック** — 古い `version` での移動は 409 で拒否、正しい `version` は 200
- **割り込み** — 実行中から他の列へ移すと `cancel_requested=1` が立つ
- コメントの投稿と表示
- **入力保護** — 外部から DB を更新して再描画を発火させても、入力中のコメントは消えない
  （ボードの表示は更新される）
- **XSS** — `<img onerror=...>` を含むタイトルは文字列として描画され、要素は注入されない

追加で確認したこと:

- ワーカー稼働中にヘッダが対象カードと作業内容を表示し、該当カードが緑枠になる
- 保存ボタンが押下時に無効化＋「保存中…」になり、完了時に成功トーストが出る
- アーカイブでボードから消え、アーカイブ一覧に現れ、復元でボードに戻る
- 削除後は詳細取得が 404 になる
