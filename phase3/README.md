# Phase 3 — カンバンボード UI

タスクストアを**ユーザーが操作できる**ようにする層。割り込み・修正・新規起票をここで行う。

| ファイル | 役割 |
|---|---|
| `Start-Board.ps1` | `HttpListener` によるローカル Web サーバと JSON API |
| `wwwroot/index.html` | UI 一式（依存ライブラリなし・単一ファイル） |

## 使い方

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\phase3\Start-Board.ps1
```

ブラウザが `http://localhost:8787/` で開く。`-Port` で変更、`-NoBrowser` で自動起動を抑止、
`-DbPath` で別の DB を見る。管理者権限は不要（localhost へのバインドは URL 予約なしで通る）。

## できること

| 操作 | 挙動 |
|---|---|
| カードをドラッグ | 列を移動。`version` を添えて送るので競合したら 409 で拒否される |
| **実行中から外へドラッグ** | `cancel_requested` が立つ。**これが割り込みの信号** |
| カードをクリック | 詳細ドロワー。判定理由・提案アクション・**ワーカーの作業ログ**・元の通知 |
| 「自分の下書き / 修正」 | `user_edited` に保存。`agent_output` は上書きしない |
| 「下書きを取り込む」 | ワーカーの生成物を編集欄にコピーして手直しする |
| 「作業を中止」 | `cancel_requested` を立てる |
| コメント | `task_comments` に積む。ワーカーは次の実行前にこれを読んで方針を立て直す |
| 「アーカイブ」 | ボードから隠す。ヘッダの「アーカイブ」から一覧・復元できる |
| 「削除」 | 確認のうえ完全削除。作業ログとやりとりも消える |
| 「まとめて削除」 | 完了・対応不要・アーカイブ済みの見出しに出る。その列のカードを確認のうえ一括で完全削除 |
| 「+ カード」 | 通知に紐づかないカードを手で起票 |
| 「?」 | 列とラベルの意味を説明するパネル |

ヘッダにはワーカーの状態（作業中 / 承認待ち / 待機中 / 停止中 / エラー）と、
いまどのカードで何をしているかが出る。処理中のカードは枠が緑になる。

## ツール実行の承認

ワーカーが危険なツール（コマンド実行・外部通信・作業フォルダ外への書き込み）を
使おうとすると、ボード上部に承認パネルが出てワーカーは停止する。

**実行内容は省略せずに表示する。** コマンド本文や URL がそのまま出る。
通知やメールの本文がワーカーの入力に混ざる以上、ここが注入と実行のあいだに立つ
唯一の壁になるため、要約で済ませてはいけない。

選べるのは、許可 / 拒否 / このカードでは以後許可 / 今後すべて許可。
「まとめて許可」はヘッダ下に一覧として残り、`×` でいつでも取り消せる。
ヘッダの「自動承認」ボタンで YOLO にもできる（有効化時に何が起きるか確認を出す）。

## 設計上の判断

**SSE ではなくポーリングにした。**
当初は SSE を想定していたが、PowerShell 5.1 の `HttpListener` は単一スレッドで回るため、
接続を張りっぱなしにするとリクエストループが止まる。ランスペースを使えば回避できるが、
一人で使うローカルボードには複雑すぎる。代わりに**安い `/api/rev`（件数と最終更新時刻）を
1.5 秒間隔で叩き、変化したときだけボード全体を取り直す**方式にした。

**入力中はドロワーを再描画しない。**
ポーリングで再描画すると、入力途中のコメントや下書きが消える（実装中に実際に踏んだ）。
`drawerBusy()` でドロワー内にフォーカスがあるかを見て、その間は作り直さない。
ボード側は更新されるので、他の変更は見える。

**表示は必ず `textContent`。**
カードには Slack のメッセージ本文がそのまま載る。`innerHTML` を使うと第三者のメッセージから
DOM を注入できてしまうため、UI は全要素を `createElement` + `textContent` で組んでいる。
元通知のリンクもクリック可能にはせず、文字列として出すだけにしてある。

**127.0.0.1 のみにバインドし、`Host` ヘッダも検証する。**
ボードには業務上のメッセージが載るので外部に露出させない。

**生の enum を画面に出さない。**
`doing` `normal` `v20` のような内部値をそのまま出すと意味が伝わらない（実際に指摘を受けた）。
`列 実行中` `緊急度 中` `版 20` のようにラベルと日本語値で表示し、
各ラベルに説明を tooltip で付け、「?」パネルに一覧を置いた。

**操作の結果を必ず画面で返す。**
ボタンは押した瞬間に無効化して「保存中…」に変わり、完了時に緑（成功）か赤（失敗）の
トーストを出す。押しても何も起きないように見える状態を作らない。

**強弱をつける。**
全部を同じ濃さで出すと、どこを見ればいいのか分からなくなる（実際に指摘を受けた）。
いま強調しているのは、カードのタイトル、緊急度「高」、成果物の有無、
着手されない状態の警告だけ。ID・種別・版といった補助情報は小さく淡い一行にまとめ、
緊急度はタグではなくカード左端の色帯で示している。
列も、見るべき列（要対応・実行中・レビュー待ち）だけ色を持たせ、
完了と対応不要は沈めている。

**長くなるものは既定で畳む。**
作業ログとやりとりは際限なく伸びるため、開いた直後に見えるのは
「成果物」と「自分の下書き」だけにした。判定理由・報告・作業ログ・やりとり・元の通知は
折りたたみで、開閉状態はカードを開き直しても保たれる。

**指示欄は複数行。**
`input` だと改行が打てず Enter が即送信になっていた。`textarea` にして、
Enter は改行、送信は Ctrl+Enter か「指示を送る」ボタンにした。
表示側も `white-space: pre-wrap` で改行を保つ。

**やりとりは入力欄が先頭、履歴は新しい順。**
古い順に積むと、増えるほど入力欄が下に逃げてスクロールが必要になる。

**一括削除は、押した時点の列をサーバ側で確かめ直す。**
ボードは 1.5 秒ごとに更新される。画面が古いまま「まとめて削除」を押すと、
その間に別の列へ移ったカードまで消えかねない。UI は見えている id を送るが、
サーバはその id のうち**いまその列にあるものだけ**を消し、残りは `skipped` として返す。
削除自体は 1 トランザクションで行うので、途中で外部キーに引っかかっても
「何枚かだけ消えた」状態にはならない。出すのは片付いた列（完了・対応不要・
アーカイブ済み）だけで、未分類や要対応には出さない。まだ見ていないものを
一掃できてしまうため。

**成功を名乗る前に応答を見る。**
削除が外部キー制約で失敗しているのに「削除しました」と表示していた（実際に踏んだ）。
状態を変える操作は、ステータスと `ok` を確認してからトーストを出す。

**パネル外のクリックで閉じる。**
ただしカードの上は除く（別のカードへの切り替えとして扱う）。
未保存の編集があるときだけ確認を挟む。

## 検証済みの範囲

ブラウザで実際に操作して確認した:

- ボードの描画、詳細ドロワーの表示
- 下書きの保存 — `user_edited` に入り、`agent_output` は変化しない
- **楽観ロック** — 古い `version` での移動は 409 で拒否、正しい `version` は 200
- **割り込み** — 実行中から他の列へ移すと `cancel_requested=1` が立つ
- コメントの投稿と表示
- **入力保護** — 外部から DB を更新して再描画を発火させても、入力中のコメントは消えない
  （ボードの表示は更新される）
- **XSS** — `<img onerror=...>` を含むタイトルは文字列として描画され、要素は注入されない

追加で確認したこと:

- ワーカー稼働中にヘッダが対象カードと作業内容を表示し、該当カードが緑枠になる
- 保存ボタンが押下時に無効化＋「保存中…」になり、完了時に成功トーストが出る
- アーカイブでボードから消え、アーカイブ一覧に現れ、復元でボードに戻る
- 削除後は詳細取得が 404 になる
